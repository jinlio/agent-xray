## 1. 统一事件模型（model.py）

全部时间用 epoch 毫秒 int；所有文本字段入库前截断（默认 2000 字符，`--full` 关闭）。

```
Session{ id, source: zcode_db|claude_code, title, app_version, cwd,
         created_at, updated_at, duration_ms, models[], turns[], child_sessions[], stats }
Turn{ id, index, started_at, duration_ms, user_text, status, model_calls[], annotations[] }
ModelCall{ id, model, provider, agent, query_source, started_at, duration_ms, attempt,
           finish_reason, usage{input,output,reasoning,cache_read,cache_write},
           cost{...}|null, reasoning_text, text, tool_use_ids[] }
ToolUse{ id, name, category(bash|file|edit|search|web|mcp|agent|todo|other),
         status(ok|error|running), input, output, error, duration_ms, exit_code }
SessionStats{ 轮数/调用数/工具数/错误数/重试数, tokens合计, cost合计,
              failures[], tool_top[], 耗时分布 }
Failure{ kind(tool_error|model_error|retry|context_exceeded|permission_denied|
              interrupted|long_turn), turn_index, at, message, ref }
```

## 2. zcode_db.py（主适配器，字段映射已勘察到 jq 路径级）

**安全读取**：默认发现 `~/.zcode/cli/db/db.sqlite`；把 db + `-wal` + `-shm` 拷到临时目录再打开（避免锁活库），`--db` 可指定。

**能力探测降级**：先查 `sqlite_master` 确认 message/part/turn_usage/model_usage/tool_usage 各表与列是否存在，缺哪张就降级（如无 usage 表 → 耗时从 part 的 time 推），永不 crash。

**重建流程**：
1. `session` 表 → Session 元信息（title/directory/time_created/task_type/parent_id/version）
2. `message` 按 `sequence` 排序拉取（`data` JSON）；`part` 按 `(message_id, sequence)` 分组挂到消息
3. **Turn 分组**：按 `data.anchor.turnId` 分组；用户输入 = `semantics.origin=="real_user" && kind=="user_prompt"`；丢弃 `uiVisibility=="hidden"` 的合成消息（todo_reminder 等，仅计入噪音统计）
4. assistant 消息 → ModelCall：tokens 取 `.tokens`（含 `cache.read/write`）、model 取 `.modelId // .modelID` 双命名兜底、finish/error 直读；**耗时与重试优先 join `model_usage`**（`assistant_message_id` 关联，取 duration_ms/retry_count/query_source），退化用 `time.completed-time.created`
5. part 映射：`tool` → ToolUse（input=`state.input`，output=`state.output`，status 由 `state.status` 映射 completed→ok/error/running，耗时=`state.time.end-start`）；`reasoning`/`text` → 思考/正文；`timeline(model_change)` 与 `compaction(compactReason==context_limit→context_exceeded 失败)` → turn 注记
6. **join `tool_usage`**（tool_call_id）补 exit_code/approval_status（denied→permission_denied 失败）/error_message
7. **join `turn_usage`**（turn_id）补 turn 时长/time_to_first_token/error_type
8. **失败收集**：tool error、message `.error`、`finish==failed`、`retry_count>0`、turn_usage.error_type/context_exceeded、session.last_outcome==interrupted、超长轮启发式（>P95 或 >5min）
9. **子 agent**：`session.parent_id` 递归挂 child_sessions（深度≤2）；父会话中 `.tool=="Agent"` 的 part 标注派生点
10. 成本：本地价格表估算（消息里 `.cost` 多为 0 仅缓存命中价，只作参考字段）

## 3. claude_code.py（experimental）

- 输入：`~/.claude/projects/<proj>/*.jsonl` 单文件或目录；逐行 `json.loads`，坏行进 parse_errors 不中断
- parentUuid 建链；`isSidechain==true` 的连续段收拢为 child_sessions（伪会话）
- content 兼容**旧版字符串 / 新版块数组**；tool_use 与 tool_result 按 `id↔tool_use_id` 跨行配对（结果并进 ToolUse）
- **已知坑必处理**：一次 API 响应拆多行、usage/costUSD 重复 → 按 `message.id` 去重后再累计
- timestamp ISO→ms；`type=="summary"` 行 → 标题候选
- 合成 fixtures 覆盖：正常轮、工具成功/失败(is_error)、legacy 字符串 content、重复 usage 行、sidechain 段、summary 行

## 4. cost.py

`prices.json` 随包分发：按 model id 小写前缀匹配（glm-*/claude-*/gpt-*），单价 per MTok（input/output/cache_read=0.1×input/cache_write=1.25×input，对齐 ccusage）；`--price-file` 覆盖；输出 CostEstimate + 按时间的累积曲线点。

## 5. cli.py

```
agent-xray [path]            # 缺省→自动发现 zcode db；.jsonl/.sqlite/目录 自动识别
  --list                     # 列出可渲染会话（标题/时间/轮数/规模）
  --summary                  # 终端结构化摘要（含失败点清单）
  -o/--out, --open, --index  # 输出位置（默认 ./agent-xray-out/）、生成后打开、目录批量+索引页
  --trunc N / --full, --db PATH, --price-file PATH
```

## 6. render（单文件 HTML，无构建步骤）

- 数据嵌在 `<script type="application/json" id="xray-data">`（天然免疫 `</script>` 注入），`</` 转义；echarts.min.js 内联进产物 → **双击即看、完全离线**；数据超 50MB 时激进截断并在 UI 提示
- 面板：①头部统计条（轮数/调用/工具/错误/重试/token/成本）②**执行时间轴**（每 turn 一行泳道：模型调用段按 query_source/model 着色、工具段按类别着色、错误段标红，点击右侧抽屉展开该次调用 request/reasoning/response/工具卡）③工具调用树（按类别→名称聚合：次数/错误率/耗时，点击跳时间轴定位）④失败列表（类型+轮次+跳转）⑤成本曲线（ECharts 累积线+尖峰标注）
- 深色主题，原生 JS，无框架无 node_modules
